# Architecting an AI harness for natural-language → polished 2D browser games

Research notes compiled 2026-10-27. Scope: how existing prompt-to-game products work and fail; academic/industry research on agentic game generation, PCG, playtesting and LLM-as-judge; harness design patterns from Claude Code / Agent SDK (skills, CLAUDE.md, subagents, hooks, verification loops); and a concrete proposed architecture.

Method note: WebSearch plus WebFetch. Many domains (arxiv.org, huggingface.co, alphaxiv, rosebud.ai, summerengine.com, roblox.com, 9to5google, fortune.com, itch.io, phaser.io, gitcode) were unreachable from this sandbox's egress proxy, so for those sources the findings below are based on search-engine summaries of the page rather than the full page. Anthropic/claude.com/code.claude.com pages were fetched in full. The per-turn WebSearch budget was exhausted before a final round of follow-ups (noted under Gaps). "Vendor claim" is marked wherever the only source is the company itself.

## Key Question 1: How do existing AI game-creation products generate games, and what fails most?

### Takeaway
Every shipping prompt-to-game product that discloses anything is a chat-driven code-generation agent sitting on a fixed runtime (Rosebud → Phaser/Three.js in-browser; Summer Engine → a Godot-4-compatible desktop engine; Google Playground → Gemini + Nano Banana + Lyria "in a custom harness"; Astrocade → a proprietary multi-model orchestrator "AstroBrain" with a brainstorm → blueprint → per-game custom edit-mode flow), paired with generative asset models. None publishes its internal pipeline. The recurring criticisms are: output is a prototype not a game (redundant, uncommented code; debugging slower than hand-writing), the demo "wow" doesn't survive real projects, controls/feel and rule-change robustness are unverified, output is locked to a hosted page, and usage is token-capped.

### Inferences
- Across products, the differentiator is not the LLM but the fixed runtime + editor + asset pipeline around it; the generation itself appears to be conversational code-gen against a known engine (Phaser for Rosebud's 2D). A harness that wants to beat them should invest in what they visibly lack: a verification loop and a design layer (progression, feel, polish), not a different code generator.
- Astrocade's "brainstorm → blueprint → custom edit mode" is the only disclosed multi-stage design flow; it is also the only product with a reported engagement-data flywheel (10M MAU). Google's choice to describe Playground as "a custom harness" around Gemini/Nano Banana/Lyria confirms that the harness, not the model, is where vendors see the work.
- The failure modes people report (prototype-grade code, demos that don't scale, controls/feel unverified, rule changes breaking things, feature regressions across rebuilds) map one-to-one to missing harness features: tests, regression gates, deterministic templates, playtest bots, and a feel/polish checklist.

- No Rosebud or Astrocade pricing/credit figures were confirmed (search budget exhausted before follow-up).
- Google's official Playground blog post was not retrieved; per-plan token limits are unpublished.

## Key Question 2: What research exists on LLM agents generating games, PCG, automated playtesting, and LLM-as-judge for quality?

### Takeaway
The literature converges on: (a) multi-agent, role-separated pipelines with retrieval grounding and engine-specific constraints (GameGPT 2023 → AutoUE 2026) to cut hallucinated API use; (b) LLM level generators are viable but only ~88% playable without a validator, so playability must be checked by a solver/simulator; (c) LLM playtest agents (Lap, TITAN) beat prior tools at coverage and crash-finding and are already deployed in real QA pipelines; (d) LLM-as-judge works for rubric-style pass/fail checks when validated against a human-labeled set, but no validated "fun" judge exists — engagement prediction still relies on agent play statistics; (e) benchmark results (gg-bench, GVGAI-LLM) show LLMs are weak at multi-turn strategy and spatial reasoning, which argues for symbolic/deterministic playtesting rather than LLM-only play.

### Cited Findings

**End-to-end agentic game generation**
- AutoUE (arXiv 2603.07106, Mar 2026; also Findings of ACL 2026): a multi-agent system that coordinates agents for model (asset) retrieval, scene generation, gameplay and interaction code synthesis, and automated game testing; uses retrieval-augmented generation grounded in Unreal tool documentation "to reduce tool-use errors"; third-party summary describes five agents (asset retrieval, scene generation, code synthesis, object interaction, play-testing), a "PlayGen-20" benchmark with game score 8.68 and scene-aesthetic score 7.8, and 100% node/parameter/pin success in PCG graph generation; ablations show predefined PCG patterns, documentation-grounded retrieval, and engine-specific code constraints each matter; limitations: 20 tasks, shallow behavioral testing; code at github.com/Pluto156/AutoUE — [arXiv abs](https://arxiv.org/abs/2603.07106); [EmergentMind summary (secondary)](https://www.emergentmind.com/papers/2603.07106); [ACL Anthology](https://preview.aclanthology.org/ingest-acl/2026.findings-acl.111/)
- GameGPT (arXiv 2310.08067, 2023): multi-agent collaborative framework for game development using "dual collaboration and layered approaches" plus decoupling to reduce hallucination and redundancy — [arXiv HTML](https://arxiv.org/html/2310.08067v2); [HF papers page](https://huggingface.co/papers/2310.08067.md)
- "90% Faster, 100% Code-Free: MLLM-Driven Zero-Code 3D Game Development" (arXiv 2509.26161) — surfaced in search; details not retrieved — [arXiv HTML](https://arxiv.org/html/2509.26161v1)
- UniGen (2025) is described in a search summary as a multi-agent Unity/Unreal framework with Planning, Generation, Automation and Debugging agents tested on three prototypes; no URL retrieved (Gap).
- Automated Unity game-template generation from GDDs via NLP and multimodal LLMs (arXiv 2509.08847): a fine-tuned LLaMA-3 turns GDDs into Unity prototypes, reporting high adherence to GDD specs — [arXiv HTML](https://arxiv.org/html/2509.08847v1)
- ScriptDoctor (arXiv 2506.06524): an LLM system that generates and tests PuzzleScript games in a loop (agentic pipeline on a DSL) — [arXiv abs](https://arxiv.org/abs/2506.06524?context=cs)
- "LLMs are the Ideal Candidate for Mixed-Initiative Game Design Pillar Workflows" (arXiv 2605.09767, 2026): argues LLMs fit mixed-initiative pillar workflows; the search summary says it has not yet shown improved design outcomes and that academia has barely studied pillars — [arXiv PDF](https://arxiv.org/pdf/2605.09767)
- GDD generation for hyper-casual games (Aydınalp et al., 2025): experts scored LLM-written GDDs higher than human-written overall, mainly on clarity and detail; roughly even on creativity and visuals — [Marmara Univ. record](https://avesis.marmara.edu.tr/yayin/fb4a6b02-1693-48eb-8849-9d6199b2e4bb/gdd-generation-for-hyper-casual-games-using-large-language-models-a-comparative-evaluation)
- A survey on LLM-based game agents (arXiv 2404.02039, v4 Nov 2025; literature through 31 July 2025) covers coordination protocols and role differentiation in multi-agent settings — [arXiv HTML](https://arxiv.org/html/2404.02039v4)
- GPT-for-games scoping review (Yang, Kleinman, Harteveld): 131 articles 2020–2024, 76 from 2024; five application areas including PCG — [arXiv 2404.17794](https://arxiv.org/pdf/2404.17794)

**Level / content generation**
- MarioGPT (NeurIPS 2023): GPT-2 fine-tuned on Super Mario Bros levels, text-promptable; "generate playable levels approximately 88% of the time"; combined with novelty search for open-ended generation; limitations: sometimes ignores prompt instructions and memorizes the dataset — [arXiv 2302.05981](https://arxiv.org/pdf/2302.05981); [NeurIPS poster](https://neurips.cc/virtual/2023/poster/71191)
- Todd et al. (FDG 2023): fine-tuned GPT-2/GPT-3 generate novel, playable Sokoban levels; performance scales strongly with dataset size — [arXiv 2302.05817](https://arxiv.org/abs/2302.05817v2); [PCG Workshop PDF](https://pcgworkshop.com/archive/todd2023level.pdf)
- PCG survey with LLM focus (Farrokhi Maleki & Zhao, AIIDE 2024) compares search-based, ML and LLM PCG and identifies gaps — [AIIDE](https://ojs.aaai.org/index.php/AIIDE/article/view/31877)
- Cerezo & Triguero: empirical comparison of traditional vs GPT-based 2D level generation incl. a ChatGPT-powered Mario level generator — [SBGames](https://sol.sbc.org.br/index.php/sbgames/article/view/37377)
- Small-language-model generation of dynamic game content (arXiv 2601.23206, 2026): rubric-based LLM-as-judge with pass/fail criteria; authors flag self-bias when the same model is teacher and judge; human annotation and cross-model validation suggest the bias only weakly transfers to the distilled student — [arXiv PDF](https://arxiv.org/pdf/2601.23206)
- Real-Time World Crafting (arXiv 2510.16952, Oct 2025): structured game behaviors from natural language; GPT-4.1 judge validated against 80 hand-labeled examples (paired Wilcoxon, significant on each criterion incl. creative alignment and emergence) — [arXiv PDF](https://arxiv.org/pdf/2510.16952)
- Unbounded (ICLR 2025, Google/UNC): "generative infinite game" with a distilled LLM generating mechanics and narrative in real time and a dynamic regional IP-Adapter for character visual consistency — [arXiv 2410.18975](https://arxiv.org/html/2410.18975v1); [ICLR page](https://iclr.cc/virtual/2025/poster/27943)
- Genie 3 (DeepMind, Aug 2025): real-time interactive general-purpose world model, 720p/24fps, consistent for "several minutes", promptable world events; research preview only — [TechCrunch](https://techcrunch.com/2025/08/05/deepmind-reveals-genie-3-a-world-model-that-could-be-the-key-to-reaching-agi); [BD Tech Talks](https://bdtechtalks.com/2025/08/07/deepmind-genie-3/). Not a code-generating game engine; not applicable to a deterministic 2D browser pipeline beyond asset/concept exploration.

**Automated playtesting**
- Lap, "Towards LLM-Based Automatic Playtest" (arXiv 2507.09490, FSE Companion '25): on the open-source match-3 CasseBonbons it achieved higher code coverage and triggered more crashes than three existing tools — [arXiv](https://arxiv.org/abs/2507.09490?context=cs)
- TITAN, "Leveraging LLM Agents for Automated Video Game Testing" (arXiv 2509.22170, Sept 2025): LLM agent for MMORPG testing; found four previously unknown bugs prior approaches missed; "deployed in eight real-world game QA pipelines" — [arXiv PDF](https://arxiv.org/pdf/2509.22170v1); [alphaXiv](https://alphaxiv.org/abs/2509.22170)
- Coverage-aware playtesting with LLM-guided RL (arXiv 2512.12706, Dec 2025): frames automated testing as necessary for frequent GaaS content updates; combines code coverage with gameplay intent — [arXiv](https://arxiv.org/abs/2512.12706)
- Roohi et al. (CHI PLAY 2021, Rovio): AI players (DRL + MCTS) predict engagement and difficulty; the combined approach beat DRL and vanilla MCTS on the hardest levels; an agent's best-case runs correlate with human data more than its average — [arXiv 2107.12061](https://arxiv.org/abs/2107.12061v1)
- MeepleLM (arXiv 2601.07251, 2026): an LLM "virtual playtester" that infers board-game dynamics from rules and models how audience groups subjectively respond; preprint, human-validation not verified here — [arXiv PDF](https://arxiv.org/pdf/2601.07251)
- Lovable/Base44/Replit test: "a polished screen does not prove that the full game loop works" — [AI Fire](https://www.aifire.co/p/ai-game-builders-tested-lovable-vs-base44-vs-replit)

**Benchmarks exposing LLM weaknesses relevant to playtesting**
- gg-bench (arXiv 2505.07215): an LLM writes descriptions of two-player strategy games, implements each as a Python Gym env, RL agents train on them; GPT-4o and Claude 3.7 Sonnet win 7–9% in-context, reasoning models 31–36%; main failures: multi-turn strategy and generalizing from description to novel scenarios — [arXiv](https://arxiv.org/pdf/2505.07215)
- RPGBench (arXiv 2502.00595): Game Creation task requires a valid, playable RPG world in a structured event-state representation with proper termination; Game Simulation checks multi-round play — [arXiv](https://arxiv.org/pdf/2502.00595v1)
- GVGAI-LLM: game-description-language benchmark; "persistent limitations of LLMs in spatial reasoning and basic planning" — surfaced via [gg-bench search context](https://www.emergentmind.com/topics/gg-bench)

**Vision-critic / screenshot-driven self-correction (web/UI code, transferable)**
- ReLook (ACL 2026): agentic RL with a multimodal LLM as visual critic scoring code from screenshots; invalid renders get zero reward; strict acceptance admits only improving revisions; critic dropped at inference for a lighter self-edit loop — [dev.to summary](https://dev.to/paperium/relook-vision-grounded-rl-with-a-multimodal-llm-critic-for-agentic-web-coding-4d0o)
- RubSE (arXiv 2608.24138, Aug 2026): rubric-guided self-evolution for UI-to-code; addresses local edits that fix one visual mismatch while regressing previously-faithful regions; gains across six VLMs and three benchmarks — [alphaXiv](https://www.alphaxiv.org/abs/2608.24138)
- Vision-guided iterative refinement for frontend code (Amazon Science / ICLR 2026 workshop): VLM critic gives structured feedback on the rendered page; the critic "only observes the rendering" — [Amazon Science PDF](https://cdn.amazon.science/e2/87/68ecc1e04ecc9e2e92bcd5fd3750/scipub-approval152129-45356067-visionguided-iterative-refinement-for-frontend-code-generation.pdf)
- Pre-operative GUI critic (arXiv 2506.04614): per-action correctness score + critique + corrective suggestion to filter errors before execution — [alphaXiv](https://www.alphaxiv.org/overview/2506.04614v2)
- VISCO benchmark: large VLMs "struggle with self-generated critiques" (a key bottleneck) — [Moonlight review](https://themoonlight.io/review/visco-benchmarking-fine-grained-critique-and-correction-towards-self-improvement-in-visual-reasoning)
- AgentVision (open-source): renders UI, runs DOM/contrast/OCR checks plus optional vision-LLM so coding agents fix issues before reporting done — [ecosyste.ms listing](https://awesome.ecosyste.ms/projects/github.com%2Famitpatole%2Fagent-vision)

**LLM-as-judge general reliability**
- LLM-as-a-judge survey (arXiv 2411.15594): strategies for consistency and bias mitigation — [arXiv](https://arxiv.org/html/2411.15594v4); second survey notes judge outputs are "sensitive to prompt template wording" — [arXiv 2412.05579](https://arxiv.org/html/2412.05579v2)
- Meta-evaluating local LLMs for serious games (arXiv 2504.12333): LLM-as-judge lacks standardized methods; reliability varies with factors like temperature — [arXiv](https://arxiv.org/pdf/2504.12333)
- Anthropic's multi-agent research system used an LLM judge with a single prompt returning 0.0–1.0 scores plus pass/fail across factual accuracy, citation accuracy, completeness, source quality, tool efficiency; "most consistent with human judgment"; for state-modifying agents, judge final state against checkpoints rather than exact steps; ~20 representative queries suffice early because effect sizes are large — [Anthropic engineering](https://www.anthropic.com/engineering/multi-agent-research-system)

### Inferences
- The research-backed recipe for generation is: role-separated agents + documentation-grounded retrieval + engine-specific constraints + predefined patterns (AutoUE's three ablated mechanisms). For a 2D harness this translates to a vetted systems/template library (the "predefined patterns"), an engine-API reference the agent must consult (the "RAG"), and lint/type rules that encode engine constraints.
- Because LLM level output is ~88% playable at best and LLMs are poor at spatial planning (GVGAI-LLM, gg-bench), level generation should be LLM-proposed but solver-validated (A*/BFS reachability, win-path check) before acceptance — the MarioGPT/Sokoban line already relies on separate playability checks.
- Playtesting should be layered: deterministic scripted bots and coverage-guided exploration (Lap/TITAN-style) for crashes and reachability; a VLM critic only for visual/UX layout issues, and only with a human-validated rubric (Real-Time World Crafting's 80-example validation is the minimum bar). "Fun" cannot currently be judged reliably by an LLM; proxy it with agent-derived difficulty/engagement curves (Roohi) and human playtests.
- The vision-critic literature's two consistent rules — reject regressions (ReLook's "only improving revisions") and guard against local fixes regressing other regions (RubSE) — argue for screenshot-diff regression gates alongside any critique loop.

### Gaps
- Could not read the full AutoUE, GameGPT, Lap, TITAN, ScriptDoctor, MeepleLM or pillar-workflow papers (arXiv and mirrors unreachable); agent names, prompts and exact metrics are from abstracts/secondary summaries.
- No paper found that validates an LLM judge of "fun" against human enjoyment ratings for 2D action games.
- No 2025–2026 paper specifically on LLM-generated 2D browser (JS/Phaser) games with automated playtesting was found; AutoUE/UniGen target Unreal/Unity.

## Key Question 3: Harness design patterns from coding agents (skills, CLAUDE.md, subagents, hooks, verification loops) as applied to game generation

### Takeaway
Anthropic's current guidance splits every instruction into non-deterministic (prompt, CLAUDE.md, skills — Claude decides) vs deterministic (hooks, deny rules, Stop hooks, tests, CI — the harness enforces), and recommends keeping CLAUDE.md short (<200 lines, only what can't be read from the repo), moving procedures into progressively-disclosed skills, using subagents for parallelism/isolation/fresh-eyes review (not for "better answers"), and above all giving the agent "a check to run that comes back pass or fail" with evidence. The Agent SDK framing is gather context → act → verify, with verification via rules, visual screenshots, or LLM-as-judge (in descending reliability).

### Cited Findings

**Skills (SKILL.md) and progressive disclosure**
- A skill is a directory of instructions, scripts and resources; only SKILL.md is required; YAML frontmatter with `name` and `description` is preloaded into the system prompt at startup; the body loads when relevant; bundled files load only when navigated to — three levels (metadata → body → linked files), making bundled context "effectively unbounded" — [Anthropic engineering: Agent Skills](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)
- Guidance on instructions vs code: LLMs are costlier than code for deterministic work (e.g., sorting); skills can bundle scripts Claude runs without loading them into context; make clear whether a script is to be run or read; keep rarely used or mutually exclusive contexts on separate paths — [same](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)
- Authoring: start from evaluation (run agents on representative tasks, find gaps, add skills incrementally); split when SKILL.md becomes unwieldy; watch `name`/`description` because they drive triggering; have Claude capture successful approaches and mistakes into the skill — [same](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)
- Claude Code skill frontmatter includes `description`, `when_to_use` (combined text truncated at 1,536 chars), `disable-model-invocation`, `user-invocable`, `allowed-tools`, `disallowed-tools`, `model`, `effort`, `context: fork` (+ `agent`, `background`), `hooks`, `paths` (glob-limited auto-activation); `$ARGUMENTS`, `${CLAUDE_SKILL_DIR}`, and `` !`command` `` dynamic injection; keep SKILL.md under 500 lines; invoked skill content persists in context; after compaction each skill's most recent invocation is re-attached (first 5,000 tokens each, 25,000-token shared budget) — [Claude Code docs: Skills](https://code.claude.com/docs/en/skills)
- `/verify` builds and runs the app to confirm a change (no fallback to tests/typecheck) and records the launch recipe to `.claude/skills/verify/SKILL.md`; `/run-skill-generator` records it up front; if a project skill named `verify` or `simplify` exists, Claude runs it before each commit (v2.1.286+) — [Claude Code docs: Skills](https://code.claude.com/docs/en/skills)
- Secondary: Anthropic released skills as an open standard on Dec 18, 2025, with OpenAI, Google, GitHub and Cursor adopting within weeks (not verified against primary) — [Progressive Disclosure Matters (Substack)](https://aipositive.substack.com/p/progressive-disclosure-matters); one practitioner post argues progressive disclosure suits "capability uplift" skills but can hurt small, always-needed "encoded preference" knowledge — [Varun Bhanot (Substack)](https://varunbhanot.substack.com/p/your-code-style-skill-is-making-claude)

**CLAUDE.md, rules, and what not to write**
- Only write what Claude can't find by reading the repo or would rediscover every session: exact test/typecheck/lint commands, misleading code areas, decisions not in the repo, anything corrected twice; keep under ~200 lines; `/init` then remove lines; `/doctor` and `/doctor prompt-audit` flag bloat and stale instructions; personal prefs in `CLAUDE.local.md` — [Claude Code best practices](https://code.claude.com/docs/en/best-practices)
- Path-scoped rules in `.claude/rules/*.md` with a `paths:` frontmatter filter load only when working there — [same](https://code.claude.com/docs/en/best-practices)
- "If you keep adding emphasis to a CLAUDE.md line and Claude still misses it, that's a sign the line belongs in a hook" — [same](https://code.claude.com/docs/en/best-practices)
- Spec-first: ask Claude to "interview me until you could write the spec, then write it to SPEC.md", then start a fresh session to build from it, and point the reviewer at it — [same](https://code.claude.com/docs/en/best-practices)
- "be ambitious" is the one phrase that still helps (scope, not effort); effort level (`/effort low|medium|high|xhigh|max`) replaces "think hard" wording — [same](https://code.claude.com/docs/en/best-practices)
- Cursor/Codex equivalents: Cursor uses `.cursor/rules/*.mdc` (glob-scoped) or a plain `AGENTS.md`; Codex CLI reads `AGENTS.md` with subdirectory scoping; always-on files add token cost on every run, so scoped rules are preferred for large convention sets — [gauravtiwari.org](https://gauravtiwari.org/cursor-rules/); [StackHawk](https://www.stackhawk.com/blog/cursor-rules/); [mer.vin](https://mer.vin/2025/12/cursor-ide-rules-deep-dive/); [Shiplight](https://www.shiplight.ai/api/blog/cursor-rules/raw)

**Hooks (deterministic enforcement)**
- Hook events include SessionStart/End, UserPromptSubmit, Stop, PreToolUse, PostToolUse, PostToolUseFailure, SubagentStart/Stop, TaskCreated/Completed, PreCompact/PostCompact, FileChanged, etc.; handler types `command`, `http`, `mcp_tool`, `prompt`, `agent`; exit code 2 blocks and feeds stderr back; JSON `additionalContext` injects facts; `PreToolUse` can rewrite inputs (`updatedInput`), `PostToolUse` can replace outputs; `Stop`/`SubagentStop` with exit 2 keep Claude working — [Claude Code docs: Hooks](https://code.claude.com/docs/en/hooks)
- A `Stop` hook running `tsc --noEmit 1>&2 || exit 2` keeps Claude working until typecheck passes; after eight consecutive blocked stops with no tool call Claude Code overrides (cap configurable via `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP`); `PostToolUse` on `Edit|Write` for formatters; `PreToolUse` to block edits to protected paths; `prompt`/`agent` hooks are not deterministic — use `command`/`http` with `onFailure: "block"` for real enforcement; keep the enforced set small ("if you ever find yourself at forty of them, most are probably preferences") — [Claude Code best practices](https://code.claude.com/docs/en/best-practices)
- `/goal <condition>` has a separate model check the condition after every turn and sends Claude back until met — [same](https://code.claude.com/docs/en/best-practices)

**Subagents**
- Defined as Markdown files in `.claude/agents/` with frontmatter (`name`, `description`, `tools`, `disallowedTools`, `model` incl. `haiku`, `permissionMode`, `maxTurns`, `skills` preloaded, `mcpServers`, `hooks`, `memory`, `effort`, `isolation: worktree`); fresh context window; only a summary returns; nesting depth 3 by default; 20 concurrent by default; description budget ~15,000 tokens; `/code-review` reviews a diff in a fresh subagent that never saw the conversation — [Claude Code docs: Subagents](https://code.claude.com/docs/en/sub-agents); [best practices](https://code.claude.com/docs/en/best-practices)
- When to use: verbose output, tool restriction, self-contained summary-returning work, routing to a cheaper model; not for iterative back-and-forth or multi-phase shared context; "handing the same task to a subagent doesn't make the answer any better. A fresh reviewer does help" — [Subagents docs](https://code.claude.com/docs/en/sub-agents); [best practices](https://code.claude.com/docs/en/best-practices)
- A read-only reviewer subagent example: `tools: Read, Grep, Glob`, "Compare the changed files against the spec... report only the gaps that affect correctness. Skip style." — [best practices](https://code.claude.com/docs/en/best-practices)
- Anthropic's multi-agent research system: lead agent plans and spawns 3–5 subagents in parallel, each with a clear objective, output format, tool guidance and task boundaries (vague instructions caused duplicated work and gaps); effort scaled by complexity (1 agent/3–10 calls for simple, 2–4 subagents for comparisons, 10+ for complex); Opus lead + Sonnet subagents beat single Opus by 90.2% on an internal eval; resume from checkpoints; full tracing — [Anthropic engineering](https://www.anthropic.com/engineering/multi-agent-research-system)

**Agent loop and verification (Agent SDK)**
- Loop: gather context → take action → verify work → repeat; context via agentic search (grep/tail on a well-structured folder tree), subagents (parallel, isolated), compaction; action via tools (prominent in context, so design matters), bash/scripts, code generation (Claude.ai's file creation uses Python scripts for Excel/PPT/Word), MCP; verification via rules-based (lint/typecheck; "TypeScript with linting gives more feedback than plain JavaScript"), visual feedback (screenshot rendered output; Playwright MCP incl. viewports), LLM-as-judge ("generally less robust and costly in latency") — [Anthropic: Building agents with the Claude Agent SDK](https://claude.com/blog/building-agents-with-the-claude-agent-sdk)
- Context engineering: context is finite ("context rot"); system prompts at the "right altitude"; few canonical examples over edge-case lists; minimal, distinct tools; just-in-time retrieval with lightweight references; long-horizon techniques: compaction, structured note-taking (persistent notes/to-do files reloaded later), sub-agents with clean contexts returning condensed summaries; "do the simplest thing that works" — [Anthropic: Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- Tool design: consolidate multi-step operations into single calls; namespace by service/resource; return high-signal natural-language fields not opaque IDs; paginate/truncate with guidance; error messages that state fixes; evaluation loop: prototype → realistic multi-step eval tasks with verifiers → run agents and track accuracy/runtime/tool calls/tokens/errors → read transcripts → have an agent refactor tools → validate on held-out set — [Anthropic: Writing tools for agents](https://www.anthropic.com/engineering/writing-tools-for-agents)
- Secondary (ML6 write-up of an AI Engineer Summit talk): the same Opus 4.5 scored 78% on the CORE benchmark under Claude Code's harness vs 42% under Smolagents, presented as evidence harness design matters as much as the model — [ML6](https://www.ml6.eu/en/blog/inside-the-claude-agents-sdk-lessons-from-the-ai-engineer-summit)

**Unattended runs, headless mode, parallelism**
- Five pre-flight questions for unattended runs: does it know what done looks like (goal/spec/failing test); can it check its own work (tests, Stop hook, review); what may it touch (permissions, sandbox, worktree, branch); what stops it (`--max-turns`, `--max-budget-usd`, spend limit); where does the result go and who signs off — [best practices](https://code.claude.com/docs/en/best-practices)
- Headless: `claude -p` with `--bare` (skips hooks/skills/CLAUDE.md; API-key auth), `--append-system-prompt`, `--allowedTools`, `--permission-mode dontAsk`, `--max-turns`, `--output-format json|stream-json`; `/batch` splits big mechanical changes into 5–30 worktree units; `claude -w` worktrees; `/loop`, `/schedule` — [same](https://code.claude.com/docs/en/best-practices)
- Browser verification: Claude Code + Claude in Chrome reads console errors and DOM, verifies UI against a Figma mock, tests flows, records GIFs, saves screenshots to disk; enabling Chrome by default increases context usage; not available via API-key auth or third-party providers — [Claude Code docs: Chrome](https://code.claude.com/docs/en/chrome)
- Anthropic internal usage: Product Design runs autonomous loops where Claude writes code, runs tests, repeats until acceptable, with human review before refinements; Growth Marketing used two specialized sub-agents to generate hundreds of ads; data scientists build React visualizations via one-shot prompts in a sandbox — [How Anthropic teams use Claude Code](https://claude.com/blog/how-anthropic-teams-use-claude-code)

**Community game-specific skills (secondary, low adoption)**
- Phaser+Playwright skill (chongdashu/phaserjs-oakwoods): for canvas/WebGL games "test seams are treated as mandatory" — expose a test hook so Playwright can switch game modes and wait on a ready signal such as `window.__TEST__.ready`; use a small harness scene with fixed modes for targeted screenshots; CI without GPU may need software-rendering flags; ~84 installs — [agentskills.so listing](https://agentskills.so/skills/chongdashu-phaserjs-oakwoods-playwright-testing)

### Inferences
- The clean mapping for a game harness: CLAUDE.md = commands + gotchas only; skills = procedures (GDD authoring, level design, juice pass, playtest protocol, asset prompting) with bundled scripts; `.claude/rules/` = engine/path-scoped conventions (e.g., rules for `src/systems/**`, `assets/**`); hooks = non-negotiables (typecheck+lint on edit, Stop hook that runs the headless playtest + budget checks, PreToolUse block on editing vetted template internals); subagents = isolated reviewer-against-GDD, playtest-bot runner, asset generator, each on the cheapest adequate model.

- Spec-first (SPEC.md → fresh session → reviewer-against-spec) maps directly to GDD-first generation with a review subagent that checks implementation against the GDD, "skip style".

## Key Question 4: What should the pipeline be, and which stages should be deterministic code vs LLM?

### Takeaway
Synthesizing the product gaps (Q1), the research (Q2) and harness guidance (Q3), the pipeline should be: intake interview → concept card → GDD with pillars → system selection from a vetted template library → deterministic scaffold → LLM-implemented glue and content against typed interfaces → solver-validated levels → asset generation under a style card → automated playtest + screenshot/VLM critique → juice/polish checklist gate → perf/size budget gate → publish. LLMs do the design, selection, authoring and critique; code does scaffolding, validation, playability solving, diffing, budgets and gating.

### Cited Findings (supporting evidence for each stage choice)
- Spec/interview-first and reviewer-against-spec are Anthropic's recommended workflow — [Claude Code best practices](https://code.claude.com/docs/en/best-practices)
- Astrocade's disclosed flow is brainstorm → "rich game blueprints" → generated per-game edit mode (vendor claim) — [NatLawReview press release](https://natlawreview.com/press-releases/astrocade-rolls-out-ai-agent-powered-game-creation-experience-opening-door)
- LLM-written GDDs for hyper-casual games were rated higher than human ones on clarity/detail — [Marmara record](https://avesis.marmara.edu.tr/yayin/fb4a6b02-1693-48eb-8849-9d6199b2e4bb/gdd-generation-for-hyper-casual-games-using-large-language-models-a-comparative-evaluation)
- AutoUE ablations show predefined PCG patterns, documentation-grounded retrieval, and engine-specific code constraints each matter — [EmergentMind summary](https://www.emergentmind.com/papers/2603.07106)
- Code is "deterministic, repeatable" and cheaper than token generation for algorithmic work; bundle scripts in skills — [Anthropic Agent Skills](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)
- MarioGPT playable ~88% of the time; Sokoban generators need playability validation — [MarioGPT](https://arxiv.org/pdf/2302.05981); [Todd et al.](https://arxiv.org/abs/2302.05817v2)
- LLMs weak at multi-turn strategy and spatial reasoning — [gg-bench](https://arxiv.org/pdf/2505.07215)
- LLM playtest agents find more crashes/coverage than prior tools and are deployed in production QA — [Lap](https://arxiv.org/abs/2507.09490?context=cs); [TITAN](https://arxiv.org/pdf/2509.22170v1)
- Verification hierarchy: rules > visual > LLM-judge — [Agent SDK post](https://claude.com/blog/building-agents-with-the-claude-agent-sdk)
- Visual critics must reject regressions and guard against local fixes breaking other regions — [ReLook](https://dev.to/paperium/relook-vision-grounded-rl-with-a-multimodal-llm-critic-for-agentic-web-coding-4d0o); [RubSE](https://www.alphaxiv.org/abs/2608.24138)
- Game-feel techniques (hit-stop 50–100 ms on heavy hits, trauma-based screen shake with squared value and noise offset, flash, particles, floating text, knockback, sprite flicker, sound coherence; "juice is seasoning, not the meal") — [Wayline game-feel lesson](https://www.wayline.io/learn/game-feel/1); [Godot forum checklist](https://forum.godotengine.org/t/game-feel-checklist-for-godot-4-hit-stop-trauma-shake-coyote-time-and-more/145340); [Mega Cat juice guide](https://megacatstudios.com/blogs/game-development/mega-cat-developer-juice-guide-v1-0-08-23-17); [eastondev](https://eastondev.com/blog/en/posts/dev/20260521-game-feedback-feel/)
- Rosebud accepts an uploaded image as a visual reference at prompt time (vendor) — [Rosebud interface guide](https://lab.rosebud.ai/blog/rosebud-ai-interface-guide)
- Canvas games need explicit test seams and ready signals for Playwright — [agentskills.so Phaser skill](https://agentskills.so/skills/chongdashu-phaserjs-oakwoods-playwright-testing)

### Inferences — proposed pipeline (deterministic vs LLM marked)

1. **Intake interview (LLM, Opus-tier, interactive).** Interview the user "until you could write the spec" (genre, reference games, session length, platform, input scheme, tone, art direction, must-haves/out-of-scope). Output: `concept.md`. Precedent: Anthropic's SPEC.md flow; Astrocade's brainstorm step.
2. **GDD with pillars (LLM).** Structured `gdd.md` from a skill template: 3 pillars, core loop (30-second/5-minute/session), player verbs, progression curve, failure/success states, content list, scope budget (levels, enemies, items), "what makes it feel good". Deterministic schema check (required sections, numeric scope within budget).
3. **System selection from a vetted template library (LLM selects, code scaffolds).** A catalog (`systems/*.md` + typed TS modules) of pre-tested systems: movement (platformer/top-down/grid), combat (melee/ranged/bullet-hell), inventory, dialogue, progression (XP/unlocks/upgrades), save/load, UI (HUD, menus, pause, settings), audio bus, camera (follow/deadzone/shake), scene flow, input remapping, accessibility (remap, screen-shake toggle, color-blind palettes). The LLM emits a `systems.json` manifest with parameters; a deterministic generator scaffolds the project (engine boilerplate, scene graph, typed config, tests, CI). This is AutoUE's "predefined patterns" and Anthropic's "code for deterministic work".
4. **Implementation of glue and bespoke mechanics (LLM, against typed interfaces).** TypeScript + ESLint for maximal rule-based feedback; `.claude/rules/` scoped per directory; PreToolUse hook blocks edits inside `templates/` internals (fork instead); PostToolUse runs prettier/eslint; Stop hook runs `tsc`, unit tests, and the headless smoke run. Reviewer subagent checks against `gdd.md`, "skip style".
5. **Level/content generation (LLM proposes, solver validates).** Levels authored as data (tilemaps/JSON) by an LLM level-design skill with a difficulty ramp spec; a deterministic validator checks reachability (BFS/A* with the movement model's jump arc), win-path existence, spawn safety, collectible counts, and difficulty metrics (path length, enemy density, required precision); reject/regenerate on failure. Seeded PCG where appropriate (deterministic code) with LLM-tuned parameters.
6. **Asset generation under a style card (LLM/image+audio models, code for post-processing).** Prompts derived from the style card (Q5); deterministic post-processing: downscale to target resolution, palette quantization to the card's palette, alpha cleanup, spritesheet packing, consistent anchor points, loudness normalization for audio. Reject assets failing palette/size checks before they enter the project.
7. **Automated playtest (code first, LLM second).** Headless run with a fixed seed and virtual clock; scripted bots per system (walk-right-and-jump, attack-nearest, menu traversal); coverage-guided random exploration (Lap-style) logging crashes, stuck states, NaNs, out-of-bounds, unreachable UI; metrics on time-to-first-action, death rate per level, completion time vs GDD target. Only then a VLM critique of screenshots against a rubric (readability, contrast, HUD occlusion, consistent style, empty-state screens) with a human-validated rubric.
8. **Polish/juice gate (checklist = deterministic lint + LLM pass).** Machine-checkable items: every hit/collect/death event wires at least one feedback channel (sfx, particle, flash, shake, hit-stop) via the template's event bus; input latency within budget; coyote time/jump buffering present in platformer movement; menus navigable by keyboard; screen-shake toggle exists. LLM "juice pass" skill proposes tuning; values clamped by code (e.g., shake amplitude max, hit-stop ≤ 100 ms).
9. **Performance/size budgets (deterministic).** Playwright run with CPU throttling: frame time p95, draw calls/sprites per frame, bundle size, asset bytes, load time; Stop hook fails over budget.
10. **Publish (deterministic).** Build, hash assets, deploy static bundle, generate share page/thumbnail (first validated screenshot), store `gdd.md`, `systems.json`, `style.json`, playtest report alongside for later iteration.

**Iteration model for users.** Every user edit request is routed by a small model into (a) parameter tweak in `systems.json`/`style.json` (no LLM code edit; regenerate deterministically), (b) content edit (level/dialogue regeneration + re-validate), or (c) code change (full loop with regression gates: screenshot diffs vs last accepted build, playtest metrics must not regress — ReLook's "only improving revisions"). Keep checkpoints per accepted build so users can rewind (mirrors Claude Code's `/rewind`).

### Gaps
- No published, measured comparison of template-scaffold + LLM-glue versus free-form LLM codegen for games; the recommendation rests on AutoUE's ablation plus Anthropic's general guidance.
- Difficulty-curve validation numbers (target death rates etc.) are not sourced; they must be tuned empirically.

## Key Question 5: How should a "style reference" be represented internally and consumed by the agent?

### Takeaway
No vendor or paper documents an internal style representation; Rosebud only exposes an uploaded reference image. The sourced harness principles (stable, cacheable prefixes; path-scoped rules; skills with bundled scripts; deterministic code for repeatable work) imply a machine-readable style card (`style.json`) that is (1) the stable prefix for every asset prompt, (2) enforced by deterministic post-processing/validators, and (3) surfaced to the coding agent as a scoped rule, not a long CLAUDE.md section.

### Cited Findings
- Rosebud's prompt box accepts an uploaded image as a visual reference (vendor) — [Rosebud interface guide](https://lab.rosebud.ai/blog/rosebud-ai-interface-guide)
- Unbounded uses a "dynamic regional IP-Adapter" to keep a character visually consistent across environments — [arXiv 2410.18975](https://arxiv.org/html/2410.18975v1)
- Prompt caching is a prefix match; keep stable content first and volatile content after the last breakpoint; cache reads cost $0.20–0.25/MTok on current models vs $4–10 input — [Claude pricing](https://claude.com/pricing); [best practices (cache behavior)](https://code.claude.com/docs/en/best-practices)
- Path-scoped `.claude/rules/*.md` and skill `paths:` frontmatter load conventions only where relevant — [best practices](https://code.claude.com/docs/en/best-practices); [Skills docs](https://code.claude.com/docs/en/skills)
- Tools should return high-signal natural-language fields and have strict schemas; "small wording changes can yield large performance gains" — [Writing tools for agents](https://www.anthropic.com/engineering/writing-tools-for-agents)
- Vision critics regress other regions when fixing one mismatch unless a rubric guards the whole — [RubSE](https://www.alphaxiv.org/abs/2608.24138)

### Inferences — proposed style card
- `style.json` fields: `resolution` (logical px, e.g., 320×180 or 480×270; integer scale factor), `pixel_art: bool` + `nearest_filtering`, `palette` (ordered hex list, max N colors, named roles: bg/mid/fg/accent/danger/ui), `outline` rules, `animation` (fps per category: idle 6, run 10, attack 12; squash/stretch allowed?), `camera` (follow type, deadzone, lerp, shake max, zoom), `typography` (bitmap font name, sizes for HUD/dialogue/title, letter spacing), `ui` (corner radius, panel texture, button states), `audio_mood` (tempo range, instrumentation words, sfx character: chiptune/organic/synth), `lighting/post` (vignette, bloom off/on, CRT shader), `reference_images` (paths + 1-line "what to take from this"), `negative` (what to avoid). Derive it from the interview + any uploaded references via a vision pass; let the user edit it as a form.
- Consumption: (1) the asset-generation skill composes prompts as `[style prefix from card] + [asset-specific description]`, keeping the card first for cache hits; (2) deterministic validators quantize to the palette, resize to resolution, check sprite bounds and animation frame counts; (3) a `.claude/rules/assets.md` and `.claude/rules/ui.md` restate only the code-relevant constraints (texture filtering, scale mode, font asset names, camera config keys) with `paths:` filters; (4) the VLM critique rubric is generated from the card so judgments are relative to the declared style, not the model's taste.
- Keep the card small and stable; version it; any change triggers a bounded regeneration (assets whose prompts changed) rather than a full rebuild.

### Gaps
- No primary source documents how any product encodes style internally; the card above is a design inference. No study found comparing consistency of image-model output with vs without a structured style prefix for game sprites.

## Key Question 6: How should the agent self-verify (headless run, unit tests, Playwright + vision critique, playthrough bots, performance budgets, polish gates)?

### Takeaway
Follow Anthropic's hierarchy — rules first, visual second, LLM judge last — and wire each check both as a dev-time command in CLAUDE.md and as a deterministic Stop/PostToolUse hook. Canvas/WebGL games need explicit test seams (ready signals, mode switches, deterministic seeds/clock); playtesting should be scripted bots + coverage exploration before any LLM critique; screenshot diffs with masked dynamic regions catch regressions; a VLM rubric must be validated against a small hand-labeled set.

### Cited Findings
- "Give Claude something it can run that comes back pass or fail": test file, build exit code, linter, fixture-diff script, "a browser screenshot next to the mockup"; ask for evidence (command + output or screenshot); `/verify` runs the app; `/code-review` uses a fresh subagent — [best practices](https://code.claude.com/docs/en/best-practices)
- Stop hook (exit 2) enforces checks before the turn ends; `/goal` re-checks a condition every turn; PostToolUse formatters; PreToolUse blocks on protected paths — [best practices](https://code.claude.com/docs/en/best-practices); [Hooks docs](https://code.claude.com/docs/en/hooks)
- Verification kinds: rules-based (TypeScript+lint gives more feedback than JS), visual feedback via screenshots/Playwright MCP across viewports, LLM-as-judge for fuzzy criteria (less robust, higher latency) — [Agent SDK post](https://claude.com/blog/building-agents-with-the-claude-agent-sdk)
- Claude in Chrome: console errors, DOM state, design verification vs mock, GIF recording, saving screenshots to disk — [Chrome docs](https://code.claude.com/docs/en/chrome)
- Canvas games: make a test hook mandatory; wait on `window.__TEST__.ready` rather than timeouts; harness scene with fixed modes; CI may lack GPU — [agentskills.so Phaser skill](https://agentskills.so/skills/chongdashu-phaserjs-oakwoods-playwright-testing); screenshot-diff helper — [claudeskills.info](https://claudeskills.info/zh-hant/skills/chongdashu/phaserjs-tinyswords/frontend-testing/); visual regression with masked dynamic elements and Playwright Clock API — [skills.cat game-qa](https://skills.cat/skills/opusgamelabs/game-creator/game-qa); inspect screenshots after each burst — [OpenAI develop-web-game skill](https://www.x-cmd.com/skill/openai/.curated/develop-web-game)
- LLM playtest agents: Lap higher coverage/crashes on match-3; TITAN found four unknown bugs, deployed in eight QA pipelines; coverage-aware LLM-guided RL — [Lap](https://arxiv.org/abs/2507.09490?context=cs); [TITAN](https://pdf.arxiv.org/pdf/2509.22170v1); [arXiv 2512.12706](https://arxiv.org/abs/2512.12706)
- AI players' best-case runs correlate with human engagement/difficulty data more than averages — [Roohi et al.](https://arxiv.org/abs/2107.12061v1)
- LLMs poor at spatial reasoning/planning — [gg-bench](https://arxiv.org/pdf/2505.07215)
- Judge validation: GPT-4.1 judge checked against 80 hand-labeled examples with paired Wilcoxon tests — [arXiv 2510.16952](https://arxiv.org/pdf/2510.16952); rubric pass/fail judges with self-bias caveat — [arXiv 2601.23206](https://arxiv.org/pdf/2601.23206); judges sensitive to template wording — [arXiv 2412.05579](https://arxiv.org/html/2412.05579v2); Anthropic's single-prompt 0–1 score + pass/fail judge and ~20-query eval sets — [multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system)
- Vision critics: zero reward for invalid renders, accept only improving revisions — [ReLook](https://dev.to/paperium/relook-vision-grounded-rl-with-a-multimodal-llm-critic-for-agentic-web-coding-4d0o); local fixes can regress other regions — [RubSE](https://www.alphaxiv.org/abs/2608.24138); VLMs struggle with self-generated critiques — [VISCO](https://themoonlight.io/review/visco-benchmarking-fine-grained-critique-and-correction-towards-self-improvement-in-visual-reasoning); DOM/contrast/OCR checks before a vision LLM — [AgentVision](https://awesome.ecosyste.ms/projects/github.com%2Famitpatole%2Fagent-vision)
- Feel parameters to lint for: hit-stop 50–100 ms, trauma shake (0–1, squared, noise offset, decays per frame, keep small), coyote time, flash/particles/floating text/sound coherence — [Wayline](https://www.wayline.io/learn/game-feel/1); [Godot forum](https://forum.godotengine.org/t/game-feel-checklist-for-godot-4-hit-stop-trauma-shake-coyote-time-and-more/145340); [Mega Cat](https://megacatstudios.com/blogs/game-development/mega-cat-developer-juice-guide-v1-0-08-23-17)

### Inferences — verification stack
1. **Static (every edit):** `tsc --noEmit`, ESLint with engine-specific rules (no `setTimeout` in game loop, no per-frame allocations in hot paths, all textures referenced exist, all scene keys registered), schema validation of `gdd.md`/`systems.json`/`style.json`/level files. PostToolUse hook.
2. **Unit tests (per system):** templates ship with tests (movement physics invariants, inventory stack rules, save round-trip, progression math monotonicity). Bespoke mechanics must add tests; reviewer subagent checks test presence against GDD content list.
3. **Headless smoke (Stop hook):** boot the game under Playwright with `?test=1`, fixed seed, virtual clock; assert `__TEST__.ready`, zero console errors, every scene reachable via the scene graph, menus traversable by keyboard.
4. **Playthrough bots:** per-level scripted solvers (using the same deterministic validator's path) plus random/coverage exploration for N seconds per scene; record crashes, stuck frames (no state change for T s), out-of-bounds, NaNs, missing audio refs. Report metrics vs GDD targets (level time, death counts).
5. **Screenshot regression:** golden screenshots per scene/state (title, HUD, pause, death, level-complete, mid-level) with masked dynamic regions; any diff above threshold fails unless the edit intentionally touched that scene.
6. **VLM critique (bounded):** a Haiku/Sonnet-tier vision pass over the same screenshots with a rubric generated from the style card and a fixed list (text legibility at 1x scale, contrast, HUD occlusion of play area, empty/placeholder art, inconsistent palette, overlapping UI). Validate the rubric once on ~50–80 hand-labeled screenshots; use its output as advisory findings, with regressions gated by the deterministic diff instead.
7. **Polish linter:** event-bus audit that every gameplay event in the GDD's "feedback" table has ≥1 feedback channel bound; clamp ranges on juice parameters; accessibility toggles exist.
8. **Budgets:** p95 frame time under 4× CPU throttle, bundle size, asset bytes, load time, memory growth over a 60 s bot run (leak check). Stop hook fails over budget.
9. **Evidence:** the agent must attach the commands run, bot report, screenshot grid, and budget table to each build; a reviewer subagent (read-only, fresh context) compares against `gdd.md` and reports correctness gaps only.

### Gaps
- No published numbers on false-positive/false-negative rates of VLM screenshot critique for games specifically; the validation-set size suggestion is borrowed from the UI-code literature.
- No source on realistic bot-run durations/costs for browser games; must be measured.

## Key Question 7: What cost/latency is realistic per generated game with frontier models in 2026, and how do products keep it affordable?

### Takeaway
Published coding-agent benchmarks put a single Claude Code task at roughly $2–8 and 10–24 minutes (8–22M tokens, mostly cached reads) at Opus-5 pricing; current list prices are $4/$20 per MTok (Opus 5.5), $2/$10 (Sonnet 5.5), $0.10/$0.50 (Haiku 5.5 ≤100K prompt), with cache reads ~5% of input price and batch at 50% off. A full game (design + scaffold + several implementation tasks + playtests + asset generation + polish) is therefore plausibly tens of dollars of API spend with Opus everywhere, and single-digit dollars if templates minimize codegen, subagents run on Haiku/Sonnet, and prompts are cache-stable. Products visibly control cost with token caps/credits (Google Playground weekly tokens, Bitmagic credits, Rosebud paid tiers) and by fixing the runtime so generation is small.

### Cited Findings
- Claude API list prices (per MTok): Fable 5.1 $10 in / $50 out / $0.25 cache read / $12.50 cache write; Opus 5.5 $4 / $20 / $0.20 / $5; Sonnet 5.5 $2 / $10 / $0.10 / $2.50; Haiku 5.5 $0.10 / $0.50 / $0.01 / $0.125 (≤100K prompt; $0.50/$2.50 above); batch processing "save 50%"; fast mode 2× price for up to 2.5× speed; US-only inference 1.1× — [Claude pricing](https://claude.com/pricing)
- Artificial Analysis coding-agent benchmark: Claude Code with Opus 5 at xhigh effort averages ~$8.23/task, ~23.6 min, ~21.8M tokens; Opus 5 medium $3.14, 12.2 min, 7.9M tokens; Opus 5 low $2.18; Codex $7.08, 10.2 min, 13.2M tokens; cost metric is pay-per-token API cost only — [Artificial Analysis: Claude Code vs Codex](https://artificialanalysis.ai/agents/coding-agents/comparisons/claude-code-vs-codex)
- Secondary/vendor-side estimate: Claude uses ~3.2–4.2× more tokens per task than Codex — [Morph comparison](https://morphllm.com/comparisons/codex-vs-claude-code)
- Agents use ~4× the tokens of chat, multi-agent ~15×; token usage explained ~80% of performance variance on BrowseComp; multi-agent economics work "only for high-value tasks that parallelize well" — [Anthropic multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system)
- Prompt cache lasts ~1 hour on a subscription and 5 minutes on API keys (subagents 5 min unless changed); every request resends the whole conversation, "discounted while the cache is warm and full price once it expires"; `/clear` between tasks; `/usage` flags long context and cache misses once >10% of usage; subagents on `model: haiku` for simple jobs; ask for short summaries back — [best practices](https://code.claude.com/docs/en/best-practices)
- Effort is the main cost/quality knob: Opus 5.5/Sonnet 5.5/Haiku 5.5 default to `medium`; `max` tends to overthink on ordinary tasks — [best practices](https://code.claude.com/docs/en/best-practices)
- Headless cost caps: `--max-turns`, `--max-budget-usd`, spend limits — [best practices](https://code.claude.com/docs/en/best-practices)
- Google Playground: free weekly token allowance, higher limits with Google One AI plans; per-plan figures unpublished — [AI Weekly](https://aiweekly.co/alerts/google-launches-playground-a-no-code-browser-game-maker-powered-by-gemini-nano); [NerdZap](https://nerdzap.com/news/google-playground-ai-game-maker-uk-roblox-build/)
- Bitmagic Games Lab provides up to $1,000 of AI credits per qualified creator — [AI Game Changers](https://aigamechangers.substack.com/p/there-will-be-ai-tools-and-ai-assistance)
- Summer Engine: free app, pay "for heavier AI usage as projects scale" (vendor) — [Summer Engine](https://www.summerengine.com/ai-game-maker)
- Rosebud: has a free tier with limits and paid plans (competitor write-up) — [Summer Engine on Rosebud free-tier limits (competitor)](https://www.summerengine.com/es/blog/rosebud-ai-free-tier-limits)
- Unbounded uses a distilled LLM to reach interactive speeds — [arXiv 2410.18975](https://arxiv.org/pdf/2410.18975)
- Small language models can generate dynamic game content judged by a rubric LLM-judge (distillation from a frontier teacher) — [arXiv 2601.23206](https://arxiv.org/pdf/2601.23206)

### Inferences
- Rough per-game envelope (API list prices, 2026): a pipeline of ~6–10 agentic tasks (GDD, scaffold config, 3–5 implementation tasks, level gen, polish) at the Opus-5 "medium" benchmark figure (~$3/task) lands around $20–30 with Opus everywhere; routing GDD/architecture to Opus and implementation/review/playtest-triage to Sonnet 5.5 (half price) and Haiku 5.5 (1/40th) with cache-stable prefixes could plausibly bring it under ~$10; image/audio generation is additional and vendor-dependent (not priced here). Latency: tens of minutes end-to-end unless stages run in parallel (Anthropic reports up to 90% research-time reduction from parallel subagents), with ~1–3 min per user edit for parameter/content changes that skip codegen.
- Affordability levers consistent with the sources: deterministic templates shrink the codegen surface (fewer tokens); cache-stable system prompt/skill prefixes (5-minute API TTL means batching stages back-to-back matters); Haiku for routing user edits, log triage, and rubric scoring; batch API (50% off) for offline asset-prompt generation and judge passes; per-game `--max-budget-usd`; distilled small models for repetitive content (dialogue barks, item descriptions) as in Unbounded / 2601.23206.

### Gaps
- No vendor publishes cost per generated game; the figures above are extrapolations from coding-agent benchmarks, not measurements on game-generation tasks.
- Image/music generation pricing (Nano Banana, Lyria, etc.) was not researched (search budget exhausted).
- No data on Rosebud/Astrocade credit consumption per prompt.

## Consolidated proposed architecture (summary for the report writer)

Repository layout (Claude Code / Agent SDK style):

- `CLAUDE.md` (<200 lines): commands (`pnpm test`, `pnpm typecheck`, `pnpm playtest --seed`, `pnpm budget`), gotchas (test seam `?test=1`, `window.__TEST__.ready`), decisions (TypeScript only, Phaser-or-equivalent fixed runtime, never edit `templates/` internals).
- `.claude/rules/`: `systems.md` (paths `src/systems/**`), `levels.md` (`content/levels/**`: data-only, must pass validator), `assets.md` (`assets/**`: palette/resolution/filtering), `ui.md`.
- `.claude/skills/`: `gdd-author/` (interview → `gdd.md`, pillar template, scope budget script), `systems-select/` (catalog browser + `systems.json` schema + scaffold script), `level-design/` (ramp spec, generator + `validate_level.py`), `asset-prompting/` (style-card composer, post-process scripts), `playtest/` (bot runner, report format), `juice-pass/` (feel checklist, clamps), `budget-check/`, `publish/` (`disable-model-invocation: true`), `verify/` (recorded run recipe).
- `.claude/agents/`: `gdd-reviewer` (read-only, Sonnet, compares diff to `gdd.md`, "skip style"), `playtester` (Haiku/Sonnet, runs bots, returns summarized failures), `art-director` (vision model, rubric from style card, advisory), `edit-router` (Haiku, classifies user edits into parameter/content/code).
- `.claude/settings.json` hooks: PostToolUse `Edit|Write` → prettier + eslint; PreToolUse block edits under `templates/`; Stop → `tsc && vitest && playtest --smoke && budget-check` (exit 2 on failure); SessionStart injects current `gdd.md` summary and last playtest report.
- Deterministic code: scaffold generator, level validator/solver, asset post-processors, bot runner, screenshot diff, budget checker, publish script.
- LLM: interview, GDD, system selection/parameterization, bespoke code, level proposals, asset prompts, juice tuning proposals, rubric critique, edit routing, review.
- User iteration: chat edits routed by `edit-router`; parameter/content edits regenerate without touching code; code edits run the full gate; every accepted build is a checkpoint users can rewind to; evidence (bot report, screenshot grid, budget table) shown with each build.
